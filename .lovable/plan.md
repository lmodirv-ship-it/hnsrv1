# تحليل منصة cour.hnapps.store (HN SRV) + خطة الاستيراد/التصدير مع TVCC

## 1) دور المنصة

هذه المنصة هي **مركز الخدمات (Service Hub / Orchestrator)** لمجموعة HN: تسجّل المواقع وخدماتها، تكتشفها آلياً، توجّه أي طلب خدمة إلى الموقع القادر على تنفيذه، وتراقب الصحة والسجلات. TVCC هي مركز المجموعة (الهوية والملكية)، وهذه المنصة هي مركز التنفيذ.

## 2) الصفحات — تحليل معمّق

**لوحة التحكم ومراقبة**
- `/dashboard` — إحصاءات عامة + خريطة المنظومة + فحص صحة شامل. يعمل.
- `/monitoring` — آخر حالة صحة لكل خدمة. يعمل، لكن جدول `service_health` فارغ حتى أول فحص.
- `/system-flow` — مخطط تدفّق النظام (عرض فقط).

**المواقع والخدمات**
- `/sites` + `/sites/$slug` — سجل المواقع. **155 موقعاً**، كلها `layer=unclassified` و`tvcc_id` فارغ (أي لم تُستورد من TVCC).
- `/services` — **611 خدمة** مسجّلة.
- `/registry` — سجل القدرات والـ manifest لكل موقع. **`site_capabilities` = 0 سجل** و`discovery_runs` = 0 → لم يُشغَّل الاكتشاف بعد.
- `/knowledge` — قاعدة معرفة من المواقع والخدمات.
- `/manara` — شبكة منارة لتبادل الإشارات بين المواقع. جاهزة، لكن **0 صادرات/واردات**.
- `/exchange` — الخدمات المتبادلة + زر مزامنة مع TVCC. **0 عملية مزامنة حتى الآن**.
- `/task-center` — مركز المهام (طلب → تحديد المزوّد → تنفيذ → إرجاع). فيه **مهمتان تجريبيتان فقط**.

**التوجيه والتنسيق**
- `/orchestration` (Hub) و`/orchestrator` (بحث خدمة بالنيّة) — وظيفتان متقاربتان في قائمتين مختلفتين.
- `/pipelines` + `/pipelines/$id` + `/subtasks` — خطوط التنفيذ. **0 سجل**.
- `/providers`, `/requests-engine`, `/routing-decisions`, `/fallback-rules` — سجلات وقواعد التوجيه. تعمل، بيانات فارغة.
- `/agents` — وكلاء HN. **0 وكيل**.
- `/network` — شبكة الخدمات وربط المواقع ببعضها.

**الاكتشاف والتكامل**
- `/discovery` — اكتشاف موقع + «مزامنة المواقع من TVCC» (مسار قديم يعتمد `TVCC_API_URL`/`TVCC_API_KEY`).
- `/schema-mirrors` — مرايا قواعد البيانات (hn-db / hn-cloud) بحالة `pending`.
- `/domain-verify` — تحقّق ملكية النطاق عبر سجل TXT.
- `/identities` — معرّفات المجموعة `A000000`. **0 معرّف**.
- `/internal-connectors` + `/api-console` — موصلات داخلية ومفاتيح API.

**إدارة**
- `/admin-users`, `/settings` (لوحة المالك + الأعلام + سجل التدقيق), `/billing`, `/auth`, `/` (الواجهة العامة).

## 3) الخلاصة التشخيصية

| الجانب | التقييم |
|---|---|
| البنية والصفحات | ممتازة (35 صفحة مترابطة) |
| البيانات | مواقع وخدمات موجودة، لكن كل السجلات التشغيلية فارغة |
| الربط مع TVCC | **غير مفعّل** — لا يوجد `TVCC_API_URL` ولا `TVCC_API_KEY` |
| ازدواجية | مساران منفصلان للمزامنة مع TVCC، وصفحتا تنسيق متقاربتان |

المنافذ العامة لدى TVCC (`hn-groupe.org`) لا تُرجع لائحة مواقع (كلها 404)، ونسخة TVCC على Lovable تطلب تسجيل دخول — لذلك الاستيراد التلقائي لا يمكن أن ينجح اليوم بدون عنوان ومفتاح صحيحين.

## 4) الخطة — مبدأ استيراد/تصدير كامل

1. **توحيد مسار TVCC**: دمج `integrations.functions.ts` و`tvcc-sync.server.ts` في مصدر واحد يقرأ `TVCC_API_URL` و`TVCC_API_KEY`، مع تجربة عدّة مسارات معروفة تلقائياً وتسجيل المحاولة والسبب عند الفشل.
2. **استيراد كل مواقع TVCC**: حفظ كل موقع مع `tvcc_id` و`layer` و`network_type`، بدون تكرار (المطابقة على النطاق لا على الاسم فقط)، وتحديث الموجود بدل إنشاء نسخة ثانية.
3. **تنظيف الازدواجية الحالية**: المواقع الـ155 فيها نسخ `www` ونسخ بدون `www` لنفس النطاق — دمجها في سجل واحد لكل نطاق.
4. **استيراد يدوي احتياطي**: في صفحة «الخدمات المتبادلة» زر «استيراد لائحة» يقبل لصق JSON/CSV أو رفع ملف، بنفس منطق الدمج — ليعمل الآن قبل توفّر المفاتيح.
5. **تصدير تلقائي يومي** (03:00) للمواقع والخدمات إلى TVCC وإلى `cour.hnapps.store` و`srv.hn-groupe.org`، مع سجل كامل لكل عملية في «سجل المزامنة».
6. **واجهة الحالة**: في `/exchange` عرض «آخر استيراد / آخر تصدير / عدد المواقع القادمة من TVCC / سبب الفشل» بلغة واضحة.
7. **الإعدادات**: إضافة `TVCC_API_URL` و`TVCC_API_KEY` عبر نموذج آمن؛ بدونهما تبقى المزامنة التلقائية متوقفة والاستيراد اليدوي هو البديل.

## 5) تفاصيل تقنية

- مصدر واحد: `src/lib/tvcc-sync.server.ts` (استيراد/تصدير/دورة يومية) واستدعاؤه من `integrations.functions.ts` و`group-exchange.functions.ts`.
- مطابقة الموقع: تطبيع النطاق (إزالة `www.` والبروتوكول والشرطة الأخيرة) كمفتاح دمج، مع `tvcc_id` كمفتاح أولوي.
- الاستيراد اليدوي: `importSitesPayload` كـ server function محمية بدور admin، تقبل مصفوفة `{name, url, id?, category?}`.
- التصدير: نفس `buildExportPayload` الحالي، ويُسجَّل في `group_sync_runs`.
- مهمة pg_cron الحالية `hn-group-daily-sync` تبقى كما هي على `hnsrv1.lovable.app`.
